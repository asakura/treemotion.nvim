*treemotion-news.txt*

Notable changes since TreeMotion 0 (in development)


===============================================================================
NEW FEATURES                                     *treemotion-new-features*

- `w`/`e`/`b`/`ge` now step through naming-convention sub-words inside a
  treesitter leaf too, e.g. `fooBar-bazQux` is four stops: `foo`, `Bar`,
  `baz`, `Qux`. Comments (or any other `@spell`-tagged span) are treated as
  prose instead, splitting into words on whitespace first, the way real
  Vim's `w` does in a text file. Controlled separately for code and prose by
  `commands.motion.subword.code` / `.prose`, each with `camel_case` /
  `.pascal_case` (boolean) and `kebab_case` / `.snake_case` /
  `.comment_marker_case` (`"none"` | `"skip"` | `"stop"`, controlling
  whether `-` / `_` next to real identifier content / a run of
  comment-opener punctuation, or a bare `-`/`_` run like Lua's `--`, splits
  at all and whether the delimiter itself becomes its own stop).
  Comment-opener punctuation is configured per treesitter language via
  `commands.motion.subword.comment_markers` (defaults include Python/Bash
  `#`, C/Rust `/`, LaTeX `%`, Vim `"`, treesitter query `;` -- a language
  with no entry has none at all, so `comment_marker_case` is a no-op there
  until configured). `:checkhealth treemotion` warns if a language *you*
  added to `comment_markers` has no treesitter parser installed, but stays
  silent about the shipped defaults, since most setups won't have every one
  of those installed. `W`/`E`/`B`/`gE` are unaffected.
